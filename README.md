# 我的工作台

把「一个聊天窗口」变成「一间按角色分工的工作室」。

- **就在 DSH 界面里**：左边侧栏点「工作台」，右边主区就是工作台 —— 不用再单开一个服务。
- **角色卡片当目录**：一屏看全所有角色，点哪张进哪张。
- **每个角色认得自己**：开场只读两小节记忆（§〇 交接 + 身份卡），不翻整个仓库。
- **所有事都在界面里做**：派单、回执、分诊、认领、写文件前问权限 —— 不用开命令行。

方法与机制参考 [淋雨家的工作台](https://github.com/mashanglinyu/luanyujia-workbench)（MIT）与
[B 站视频里那一版「面板工作台」](https://www.bilibili.com/video/BV15mnJ6YELj)。本实现是它的**跨平台重写**：
去掉 Electron、去掉 Windows 硬编码、去掉命令行、**去掉独立服务** —— 直接住在 DSH 引擎里。

---

## 怎么跑起来

**已经是装好的状态**：

```bash
dsh web          # 引擎起来就行，工作台跟着一起起来
```

打开 **http://127.0.0.1:3080**，左边侧栏有一个 **工作台** 按钮（图标是四宫格，在「插件」和「自动化任务」中间）。
点它 ⇒ 右边主区就是工作台。

> **不用再 `node backend/server.mjs`**：工作台已经做成 DSH 插件（`@local/workbench`），
> 界面和 API 都由引擎自己提供（`/workbench/*`）。

### 改完代码怎么生效

插件是**软链接**装进 profile 的（`link:` 依赖），所以：

| 改了什么 | 怎么办 |
|---|---|
| `frontend/web/` 里的界面（app.js / panels.js / style.css） | 刷新页面就好 |
| `backend/server.mjs`（后端路由与逻辑） | 刷新页面就好 —— 插件模式每次请求都重新加载它 |
| `backend/index.js` / `frontend/client.js`（插件胶水） | 在插件管理器里把「工作台」关掉再打开（会重启引擎进程） |
| `backend/lib/` 里的模块 | 同上：关掉再打开（ESM 按 URL 缓存模块 ⇒ 老的还在用着）<br>例外：`backend/lib/actlog.mjs` / `backend/lib/memory.mjs` / `backend/lib/vault.mjs` / `backend/lib/derive.mjs` 借了 `backend/server.mjs` 的时间戳加载 ⇒ 刷新就生效 |

### 想单独开一个页面看看

```bash
cd workbench
node backend/server.mjs          # 零依赖，不需要 npm install
```

打开 **http://127.0.0.1:3081**。这是**独立模式**（同一个界面、同一套 API，只是不在 DSH 界面里）。
两种模式可以并存，但**面板端口（3082…）只能有一份** —— 谁先起谁占着。

### 第一次用：连一下引擎

工作台把 DSH 引擎界面**内嵌**在 AI 面板里（靠引擎的 cookie）。

| 情况 | 要做什么 |
|---|---|
| 同一个浏览器里已经打开过 DSH 界面 | **什么都不用做** —— cookie 按主机共享，端口不影响 |
| 换过浏览器 / 新开的浏览器 | 点右上角 **「引擎」**，把 `dsh web` 启动时打印的 `http://127.0.0.1:3080/?token=XXXX` 里那串 token 贴进去，点「连接」 |
| 引擎重启过（token 变了） | 同上重新贴一次；或把新 token 写进 `backend/data/token.txt`，工作台会自动用 |

> 插件模式下**用不着**这一步：工作台的 API 跑在引擎进程里，
> 浏览器手上的 cookie 直接就够（引擎自己的路由也是这个口径）。
> 独立模式才需要贴 token。

## 它是怎么嵌进 DSH 的

```
DSH 引擎进程（唯一一个进程）
├── http://127.0.0.1:3080/            DSH 界面本体
├── http://127.0.0.1:3080/workbench/* 工作台的界面 + API（插件注册的路由）
└── http://127.0.0.1:3082…3087        面板代理端口（每个 AI 面板一个，独立 origin）
```

| 零件 | 在哪 | 干什么 |
|---|---|---|
| **Host 半边** | `backend/index.js` | 注册 `/workbench` 路由（界面 + API）；起面板端口；加工嵌入用的 CSS/JS |
| **Client 半边** | `frontend/client.js` | 侧栏注册「工作台」按钮；主区注册面板（key = `workbench`） |
| **装配** | `cordis.patch.yml` | 插件行 + 配置（工作台目录、挂载路径） |
| **显示资料** | `frontend/locale/zh.json` / `frontend/locale/en.json` / `frontend/icon.svg` | 插件管理器里显示的名字、说明、图标 |

### 为什么不是 iframe

Harness 的规矩明写着：插件页面要在槽里渲染，**不要让 Host 发一个 HTML 页面再塞进 iframe** ——
iframe 里的文档拿不到宿主的 theme token、浅色/深色切换和 `ctx.locale`。

所以工作台的 DOM 挂进 **shadow root**：

- 工作台的样式不会漏出去污染 DSH 界面，DSH 的样式也进不来（互不串味）
- theme token（`--dsw-alias-*`）照常继承（自定义属性穿过 shadow 边界）
- locale 走不到（工作台目前是纯中文界面，这是已知取舍）

### 为什么 AI 面板还要单独开端口

引擎只用一个 localStorage 键记住「上次会话」，**不区分面板** ⇒ 共用 origin 就会互抢会话。
一板一端口 = 一板一 localStorage = 天然隔离。

> 这些端口由**引擎进程自己**开（不是另一个服务），所以整台机器上仍然只有 `dsh web` 这一个进程。

## 对话区里的浮动终端

会话标题旁（`创造模式` 右边）挂着一个 **「终端」** 按钮。点一下 ⇒ **对话区上方浮出一块真终端**，
不是塞进右侧栏。里面是本机 zsh（DSH 自带 xterm.js + node-pty 的真 PTY），敲 `claude` 就是你
自己那套 Claude Code 交互界面（CLAUDE.md / hooks / MCP 全都生效），跟插件的 headless 会话互不相干。

| 位置 | 说明 |
|---|---|
| 代码 | `frontend/client.js`（Client 半边） |
| 依赖 | `package.json` 的 `dsh.client.inject` 加了 `@deepseek-ai/dsh-client-ui-sidebar-right` |
| 生效 | **要重启 `dsh web`** —— 客户端 bundle 是启动时预编译并按 rev 缓存的（`/plugins/??…&rev=…`，immutable cache） |

### 三个坑（都踩过）

1. **`openTab` 不认 `destination`**。`ctx.sidebarRight.openTab('terminal', { destination: 'float' })`
   里的 `destination` 会被**丢掉** —— 只有 `openResource` 那条路才处理它。
   正确姿势是两步走：`openTab('terminal')`（先进右栏）→ `sidebar.float(tab.id, rect)`（再拖成浮动面板）。
2. **取服务要用 `ctx.get('sidebarRight')`，不能写 `ctx.sidebarRight`**。
   属性代理是在 fiber 创建时装的，而工作台这个 fiber 早于右栏插件 provide 服务 ⇒ `ctx.sidebarRight` 是
   `undefined`，但 `ctx.get('sidebarRight')` 是实时的。
3. **React 组件的第一个参数是 props**。`function FloatTerminalButton(props)` 里要写 `props.ctx`，
   写成 `function FloatTerminalButton(ctx)` 就会拿到 props 对象（`ctx.get` 是 undefined），点起来没反应。

浮动矩形是**视口像素**：`{ x, y, width, height }`。面板可以自己拖大拖小，也能拖回右栏（dock）。

## 界面长什么样

左边 DSH 侧栏 → 点「工作台」；工作台自己的顶栏三个页签 —— **场景 / 注册 / 工作台**。

**场景页 = 左边场景树 + 右边摘要卡**；**双击摘要卡 ⇒ 进详情页**（正式面板，能编辑/能浏览/能对话）。

场景页 = 左边场景树 + 右边摘要卡（照视频里那版「场景-记忆机制」界面做的）：

```
┌ 工作台 · 场景 ──────┐  ┌ ⌘ 命令 ─────────────────────────────┐
│ ▾ 生活 ③            │  │ 日常指挥台；兼规则负责人      [打开场景]│
│   📖 阅读           │  ├───────────┬───────────┬────────────┤
│   🏊 运动           │  │ 身份卡     │ 项目信息   │ 索引        │
│   🪞 自我复盘       │  │ > 每场读的…│ - 现在干到…│ 命令 …      │
│ ▾ 工作 ④            │  │ 我是谁     │ - 下一步    │ _文件索引…  │
│   💻 前端开发 …     │  ├───────────┴───────────┴────────────┤
│ ▸ 系统 ①            │  │ 体检         │ AI 会话                 │
└─────────────────────┘  └──────────────────────────────────────┘
```

- **左边是树**：分类是枝（可折叠，状态记在本地），角色是叶；点一个角色 ⇒ 右边换成它的卡
- **分类（枝）是纯容器**：点它**只展开/折叠**，不产生导航、不出属于它自己的内容卡；
  分类名**不跟角色名重名**（避免「看着像菜单、点进去空」的错觉）；
  右边只显示**显式选中**的角色，没选中就是一句中性提示，不默认替用户挑第一个
- **可以拖**，但**层级规则是硬的**：
  - **一级菜单（分类）只能换位置** —— 永远是枝，拖到别的分类上是「两个分类换先后」，
    它的成员归属一个都不改（绝不会变成别人的二级菜单）
  - **二级菜单（角色）可以随意** —— 拖到角色上/下 = 换顺序；拖到分类标题**下半区** = 加入该分类（归属跟着变），**上半区** = 排到那个分类前面（只换顺序，归属不变）
- **右键菜单**：
  - 角色 → 改名… / 换分类… / 删除这个场景
  - 分类 → 改分类名… / **在这后面加分类** / 删掉这个分类（只删分类，角色移到「未分类」）
- **树底部有「＋ 新分类」** —— 分类可以**先建出来（空的）**，再把角色拖进去
- **分类的「定义 + 先后」存在 `backend/scenarios/_categories.json`**（注册表）——
  所以**空分类也存在**、顺序进版本库，换机器也不丢
- 角色**在组内**的先后存在 `backend/data/scene-order.json`（不提交）
- **右边是摘要卡**：身份卡 / 项目信息 / 索引 / AI 会话 / 操作留痕，每张卡是那个面板的**真实内容摘要**
  （不是占位灰条 —— 身份卡卡里就是身份卡的内容）
- **双击任意一张摘要卡 ⇒ 打开该角色的详情页**（正式面板：可编辑的记忆、索引、书架、会话…）
- 旧的「整页卡片网格」**已经删掉**

```
┌─ 我的工作台 ─────────────────────────────────────────────┐
│  场景            注册            工作台        ● 引擎已连 │
├──────────────────────────────────────────────────────────┤
│  场景页 = 卡片目录（按分类分组的角色卡）                     │
│   ┌────────┐ ┌────────┐ ┌────────┐                        │
│   │⌘ 命令  │ │◎ 调研  │ │✓ 审校  │   图标/名字/分类/       │
│   │系统     │ │工作     │ │工作     │   一句话职责/技能标签/  │
│   │派单 分诊│ │查资料…  │ │审校…    │   面板数/会话绑定/[打开] │
│   └────────┘ └────────┘ └────────┘                        │
├──────────────────────────────────────────────────────────┤
│  点开一张卡片 = 它的面板组（固定五个）                       │
│   身份卡 · 项目信息 · 索引 · 体检 · 会话                     │
└──────────────────────────────────────────────────────────┘
```

| 页签 | 干什么 |
|---|---|
| **场景** | 卡片目录（首页）。点卡片进场景详情，看这个角色的记忆/体检/会话 |
| **注册** | 登记新角色 = 建场景 + 记忆骨架 + 一条常驻会话。已登记的名单**按分类分组**，跟场景页那棵树同一套顺序 |
| **工作台** | 仪表盘（状态 + 现在该做什么）、派单台、分诊、权限与写痕 |

**卡片目录是首页** —— 这正是视频里那个博主做对的第一件事：
角色多起来以后，「先找哪个面板」比「先看哪页文档」重要。

## 五根柱子（视频里「我加的那一层」）

| 柱子 | 落在哪 | 干什么 |
|---|---|---|
| **场景体系** | `backend/scenarios/*.json` + 卡片目录 | 有几个角色、每个角色是什么 |
| **记忆** | `backend/memory/<角色>/项目信息.md` + `身份卡.md` | 一个角色一个记忆核心文件，开场只读 §〇 + 身份卡 |
| **索引** | `backend/memory/_共享记忆/索引.md`（自动生成） | 文件多了只看索引，不全量扫目录 |
| **宪法** | `backend/memory/_共享记忆/AGENTS.md` | 全局规矩，每轮都守 |
| **体检** | 场景页「体检」面板 + `GET /api/doctor`（24 项） | 哪里坏了，当场看见 |

> 博主的核心痛点是「**每次开场要读的量**」—— 他的 `项目信息.md` 已经 99.2K，
> 才需要 25K 红线 + 压缩 + 索引三层。这里把记忆**收敛成一个文件**，
> 并规定开场只读 §〇（≤4KB）+ 身份卡，量才真压得住。

### ⚠ §〇 只能有一段

`§〇` 是靠 `## §〇` 那行标题认出来的。**同一个标题出现两次 ⇒ 只有最后一段算数**，
前面那段成了死字（面板不显示它、AI 读到的也是后面那段）。

- 常见成因：在文件**末尾**手写了一段 §〇（而不是写进文件头部那一段）
- 症状：面板里 §₀ 的内容跟你以为的不一样；或者改完保存，别的节被写坏
- 体检：面板底部会红字提示「文件里有 N 段 §〇」；服务端 `mem.health()` 也报
- 修法：`node backend/dev/去重交接.mjs`（只报告）／`--apply`（真改，原文件备份到 `backend/data/去重备份/`）

> ⚠ 为什么会踩这个坑：以前 `writeSection` 找节标题用的正则是
> `/^##\s*(§[〇一二三四五六七八九十]+)\b/` —— **`\b` 在 `§〇` 后面不成立**
> （`〇` 不是 ASCII 词字符）⇒ 一节都匹配不到 ⇒ 每次保存都往文件**末尾追加**一节新的。
> 现在改成不用 `\b`，并且写入前会先把正文里夹带的节标题行剔掉。
> 自检：`node backend/dev/check-derive.mjs` 第一节。

## 记忆结构（合并版：一个核心文件 + 一张身份卡）

```
backend/memory/<角色>/
├── 项目信息.md        ← ★ 唯一记忆核心文件
│     ## §〇 当前交接   开场先读这一节，≤4KB（红线，体检会盯）
│     ## §一 场景清单   这类活的形状 / 有几个面板
│     ## §二 资产路径   东西在哪
│     ## §三 阅读台账   ← 自动派生（阅读角色）：书库现状，不用手填
│     ## §五 资产索引   文件多时 AI 只看索引，不全量扫目录
│     ## §六 协作       跟别的角色怎么搭界
├── 身份卡.md          ← 每场读的那张卡：我是谁、干什么、能碰什么
├── 项目记忆/          ← 随手笔记（note 面板落这里）
└── _文件索引.md        ← 这个角色有哪些文件（自动维护）

backend/memory/_共享记忆/
├── AGENTS.md          ← ★ 宪法（全局规矩，每轮都守）
├── 索引.md            ← ★ 索引（自动生成：角色索引 + 资产索引）
├── 派单机制.md / 修改权分档.md / GPU优先.md（详细版，AGENTS.md 会引用）
├── _待办.md / _跨场景通知.md（共享板）
└── _回执/<编号>.md（回执落盘处）
```

**两条铁律**

1. **记忆在文件里，不在会话里** —— 会话会被换掉。
2. **§〇 当前交接 ≤ 4KB** —— 超了就是红线，体检报出来。

> **为什么是「合并」而不是「四个文件」**：原仓库把记忆拆成「定位卡 / 场景画像 / 场景私有记忆 / §〇交接」四份，
> 每开场要挑着读几份，还容易各写各的。视频那一版收敛成一个 `项目信息.md`，
> 分节（§〇/§一/§二/§五/§六）代替分文件 —— 挑着读还是挑节读，但**只剩一个入口**。
> 身份卡单独放，是因为它**最稳定**（我是谁、我的地盘），适合每次开场必读。

### 身份卡是「职责」与「技能」的唯一来源

场景页头部那行**职责**和右上角那排**技能标签**，读的是身份卡里的两行
（`- 职责：…` / `- 技能：…`，技能用 `/` 分隔）——**改了身份卡，头部当场跟着变**。
`backend/scenarios/<id>.json` 里的 `duty` / `skills` 降级成兜底（卡里没写、或是 `TODO` 这类
占位符时才用）。判据是 `loadScenes()`（`backend/lib/scenes.mjs`）从卡里派生，
界面、注册页名单、派单、体检看到的是同一份。

新建角色时，注册页填的职责和技能会直接写进身份卡（`backend/lib/memory.mjs` 的 `scaffold`），
从第一天起卡就是全的。

> 回归验证跑 `node backend/dev/check-card-sync.mjs`（真实界面走一遍：逐个角色对头部、
> 改卡保存后头部当场变、改回后还原）。

## 自动区：能算出来的就别手填

**手填的「当前交接」必然过期** —— 页码变了、书读完了、换书了，但交接还是昨天写的那几行。
所以「能按真实数据算出来的」那部分，由工作台**自动派生**。

以「阅读」角色为例，书库（Obsidian 的 `05-Bookshelf/书籍list/`）才是真相，
`项目信息.md` 里那两段是**算出来的**，不是人填的：

```
## §〇 当前交接

<!-- 自动:reading.summary:start -->
- 正在读：《示例书》30/300 页（10%） · 示例作者
- 台账：在读 2 · 想读 5 · 已读完 3 · 共 10 本
<!-- 自动:reading.summary:end -->

- 下一步：读完写一段「一句话 + 三条要点」      ← 手写，自动区不管
- 卡点：（等谁 / 等什么）                      ← 手写，自动区不管
```

### 三条规矩

1. **自动区只读** —— 面板里画成灰框（标着「自动 · 只读」），不在输入框里；
   服务端写节时也用磁盘上的原自动区盖回去 ⇒ 人改不动，只有派生器能写。
2. **自动区永远在节的最上面** —— §〇 的摘要在最前 ⇒ 开场先读先看见。
3. **手写部分照旧** —— 「下一步 / 卡点」这些还是你自己写，自动区不吞字。

### 面板怎么占地方

「项目信息」面板的正文区是**撑满高度**的：页签钉在顶上、输入框吃掉剩下的高度、底栏钉在底下。
（以前 `.panel-body` 是普通块容器 ⇒ 输入框只有两行高，展开成全宽时下面一片空白。）

页签排成**一行**，窄面板里横向滚 —— 300px 宽的面板里 8 个页签以前要占两行，挤掉正文区。
想看全宽：点面板右上角的 **▲**。

### 什么时候重算

| 触发 | 干什么 |
|---|---|
| 书架点「更新进度」 | 写完书的 `currentPage` ⇒ 重算 §〇 摘要 + §三 台账 |
| 书架点「＋ 加一本」 | 书库多一本 ⇒ 重算台账（共 N 本变了） |

改的是**你的 Obsidian 原文件**（`currentPage` / `status` / `endDate`），
工作台这边只是照着它重算一遍摘要，不另存一份。

### 「正在读」那本怎么定

看留痕里**最近一次「更新阅读进度」**动的是哪本书 —— 那是人刚刚碰过的那本，最贴近「我正在读」。
（那本要是已经读完了，就往前找还在读的；都没有就取 `status=在读` 里开始日期最新的。）

### 代码在哪

- `backend/lib/derive.mjs` —— 派生器：读书库 → 算出摘要和台账 → 写回 `项目信息.md`
- `backend/lib/memory.mjs` —— 自动区机制：`parseAuto` / `setAuto` / `mergeAuto`
- `backend/server.mjs` —— `POST /api/vault/progress`、`POST /api/vault/book` 成功后触发重算
- 自检：`node backend/dev/check-derive.mjs`（逻辑）、`node backend/dev/check-derive-ui.mjs`（真实界面）

> ⚠ 插件模式下 ESM 按 URL 缓存模块 ⇒ `backend/lib/` 下的改动要立刻生效，
> 得走 server.mjs 里那个**带时间戳的 import**（`?wb=…`）。`mem` / `vault` / `derive` 都这么导入。

## 加一个角色（不用写代码）

两条路：

1. **界面**：注册页填「名字 / 职责 / 分类 / 技能」→ 自动生成
   `backend/scenarios/<id>.json` + `backend/memory/<id>/{项目信息.md,身份卡.md,_文件索引.md}` + 一条常驻会话，
   **并且自动登记进地盘表**（不登记的话，它的记忆目录算「未登记」⇒ 它连自己的记忆都写不了）。
   分类是**下拉**（选项来自分类注册表，末尾一项「＋ 新建分类…」可当场建）——
   手输容易打出跟注册表对不上的名字，变成注册表里没有、只有场景认的孤儿分类。
2. **手写 json**：`backend/scenarios/<id>.json`，**文件名必须等于 id**，否则卡片目录里不出现。

```jsonc
{
  "id": "research",
  "name": "调研",              // 卡片上显示的名字
  "description": "查资料、做笔记",   // 卡片上的一句话职责
  "icon": "◎",
  "category": "研究",           // 卡片分类（目录按分类分组）
  "duty": "查资料/做笔记",       // 分诊时用来判「唯一对口」
  "skills": ["检索", "摘要"],     // 卡片上的技能标签
  "panels": [ /* 面板组，见下 */ ]
}
```

> 卡片上的字段（图标/分类/职责/技能）**纯数据** —— 想调样子改 json 就行，不用碰代码。

### 把真实项目目录挂给一个角色

场景详情页有「**项目目录**」面板：填一个绝对路径（比如 `/Users/你/Projects/my-app`）→ **绑定**。

绑上之后：

- 这个角色的 AI 会话可以**以它为工作目录** ⇒ 让 AI 直接在那儿写代码
  （面板上有「用这个目录开一条会话」，开出来的那条会话 cwd 就是项目目录）
- 文件面板能浏览它 —— 面板里就是一棵 **VS Code 那样的文件夹树**（见下）
- 它登记成这个角色的地盘 ⇒ **别的角色碰它就是越界（E 档）**，只能提请求

> ⚠ 挂项目目录 = 把一块真实磁盘的地盘交给某个角色。
> 解绑 = 摘掉那条地盘登记（本地脚本 `backend/dev/登记地盘.mjs` 会同步）。

### 文件树（VS Code 那种：能展开、能建文件夹）

「项目目录」面板里不是一列 `ls` 结果，而是一棵**树**：

```
~/Projects/my-product           ← 绑给「总项目」角色
├── 📁 admin-web
│   ├── 📁 bin
│   └── 📁 dist
├── 📁 delivery-app
├── 📁 campus-app
├── 📁 student-app
└── 📁 teacher-web
```

怎么用：

| 想干什么 | 怎么做 |
|---|---|
| 看下一层 | 点文件夹（或点它左边的 `▸`）⇒ 展开 / 收起；展开是**懒加载**（只拉要看的这一层） |
| **建文件夹** | 工具条「**＋ 新建文件夹**」⇒ 在目标文件夹下面冒出一行输入框 ⇒ 敲名字 ⇒ 回车 |
| 建文件 | 工具条「**＋ 新建文件**」⇒ 同上 |
| 在某个文件夹里建 | 先在树上点那个文件夹（它会高亮，工具条右边写明「落点：…」），再建 |
| 上传到这个文件夹 | 右键文件夹 ⇒「上传文件到此处…」 |
| 在这个文件夹里开会话 | 右键文件夹 ⇒「在这里开一条会话」（那条会话 cwd 就是它） |
| 看文件内容 | 点文件 ⇒ 面板底部开一个小预览（前 200 行） |
| 刷新 | 工具条「⟳ 刷新」 |

规矩跟别处一样：

- **只能建在这个角色自己的目录里** —— 绑的项目目录，或它的 `backend/memory/<角色>/项目记忆/`
  （没绑项目目录时，树根就是它的「项目记忆」目录）
- 建之前走**同一套分档判定**（`backend/lib/authority.mjs`）：别人的地盘 ⇒ 拒建并说明理由
- 建完**留痕**（写痕 + 操作留痕各一笔）

> 判据：树的数据在 `backend/server.mjs` 的 `handleFsTree` / `handleFsCreate`；
> 界面在 `frontend/web/panels.js` 的 `PANELS.project`。
> 回归验证跑 `node backend/dev/check-filetree.mjs`（在**真实界面**上看树、展开、新建文件夹）。

### 左树拆成两个视图（角色 ⇄ 项目）

机主原话：「我在工作类下面，可能会有很多工作的文件，做在项目目录里的做成树形结构的菜单形式」
⇒ 左树里要有项目目录的树。

**但不能把文件树直接塞进角色树** —— 塞进去必然不直观，两个原因都是磁盘结构自带的：

1. **同一个磁盘会显示成六七份。**
   「总项目」角色绑的目录（`~/Projects/my-product`）恰好是另外几个角色目录的**父目录**：

   ```
   ~/Projects/my-product          ← 总项目
   ├── admin-web                  ← 管理端
   ├── delivery-app               ← 交付端
   ├── campus-app                 ← 校区端
   ├── student-app                ← 学生端
   └── teacher-web                ← 教师端
   ```

   按角色各挂一棵 ⇒ 同一份磁盘被复制成六七棵大分叉树。
2. **角色行和目录根认不出来。**
   `💻 总项目 📁` 下面紧跟着 `📁 my-product` —— 同名、同一个 📁 图标，只差 16px 缩进。
   那个 📁（这角色有地盘）和下一行的 📁（这就是那个目录）是同一个符号两套意思。

所以**把「项目」从角色树里拆出来，升成一级视图**；角色与项目之间用**引用**连接，不是**包含**：

```
工作台 · 场景          [ 角色 12 │ 项目 7 ]     ← 顶上的切换器
```

| 视图 | 左边长什么样 |
|---|---|
| **角色** | 分类是枝、角色是叶，**树是干净的** —— 里面一个文件都不掺 |
| **项目** | 一棵**真实磁盘**的树，按路径的父子关系嵌套；每个目录节点上挂着**谁绑了它**的角色 chip |

项目视图长这样（一份磁盘一棵，不是六七棵）：

```
📂 my-product          [💻 总项目]
  📂 admin-web          [🖥️ 管理端]
  📂 delivery-app       [📦 交付端]
  📂 campus-app         [🏫 校区端]
  📂 student-app        [🎒 学生端]
  📂 teacher-web        [🧑‍🏫 教师端]
📂 05-Bookshelf         [📖 阅读]
```

- **角色 → 项目**：角色行右边那个 📁 标记**可以点** ⇒ 跳到项目视图并定位到那个目录（滚过去 + 闪一下）
- **项目 → 角色**：点目录节点上的角色 chip ⇒ 跳回角色视图并选中那个角色
- **嵌套按磁盘路径算**：`admin-web` 是 `my-product` 的子节点，不是并列
- **绑过角色的目录不重复列**：它在磁盘上那一层不出现（已经单独画成 📂 节点了）
- 展开是**懒加载**（只读要看的这一层），展开状态记在 `localStorage`（`wb.filetree.open`）
- 上次看的哪个视图记在 `localStorage`（`wb.tree.view`）⇒ 刷新还是那个

**深目录不用一层层点**：项目视图和详情页面板都有**搜索框**（按文件名搜），
底下还带**面包屑**（点任一段跳过去）。

> 判据：`frontend/web/app.js` 的 `buildProjectTree` / `renderProjectTree`（界面）
> + `backend/server.mjs` 的 `handleFsSearch`（`/api/fs/search`，递归但跳过 `.git` / `node_modules`）。
> 回归验证跑 `node backend/dev/check-filetree.mjs`（六条判据：角色视图没有文件树、
> 项目根与角色归属正确、父子嵌套、懒加载、搜索命中、新建文件夹真建出来）。

### 书架（读你的 Obsidian）

**书架只挂在「阅读」这一个模块下** —— 别的模块不该有书架。

挂不挂书架看的是**场景自己声明的 `vaultDirs`**（`backend/scenarios/<角色>.json`）：

```jsonc
"vaultDirs": [ { "kind": "books", "dir": "05-Bookshelf/书籍list", "title": "书架" } ]
```

- 声明了 `kind: "books"` 的场景 ⇒ 详情页多一个「**书架**」面板（现在只有 `reading`）
- ⛔ **绑了同一个 Obsidian 库（`projectRoot`）不算挂书架的理由** ——
  别的场景也可能指着那个库，但书架归阅读一个模块。
- 判据只有一处：`frontend/web/app.js` 的 `renderSceneDetail`（按 `vaultDirs.kind === 'books'` 挂）；
  回归验证跑 `node backend/dev/check-shelf.mjs`（在**真实界面**上逐个场景看有没有书架面板）。

面板直接读你**真实**的 md（不是复制一份）：

```
📊 总计 10  📖 在读 2  📋 想读 5  ✅ 已读完 3
📖 在读（2）
   [封面] 示例书名  示例作者 · 300 页 · 2026-01-01 · 在读
           🟩🟩🟩⬜⬜⬜⬜⬜⬜⬜  30%
           90 / 300 页                    [继续] [更新进度]
```

- **点一本书** ⇒ 打开读书视图（正文按 markdown 渲染）
- **更新进度** ⇒ 改那个 md 的 frontmatter（`currentPage`；填满 ⇒ 状态自动变「已读完」、
  写 `endDate`）—— **改的是你 Obsidian 里的原文件**，Obsidian 那边立刻能看见
- **＋ 加一本** ⇒ 按 Obsidian 的书笔记格式新建一个 md（title/author/totalPage/status/cover）

> 判据：`backend/lib/vault.mjs`（frontmatter 解析 / 读写只写一处）。

### 上传文件

「项目目录」面板下面就是**上传区**：

- **把文件拖进去** ⇒ 传到该角色的目录
  （绑了项目目录就传进项目目录；没绑就传进 `backend/memory/<角色>/项目记忆/`）
- **选择文件** ⇒ 选若干个文件
- **选择文件夹** ⇒ 整个文件夹连目录结构一起传（`src/a.ts` 这种结构会保留）
- **传到树上某个文件夹里** ⇒ 先在树上点中那个文件夹（工具条右边会写「落点：…」），再传；
  或右键那个文件夹 ⇒「上传文件到此处…」

规矩跟别处一样：**传到哪儿由「哪个角色」决定**，传不进别人的目录；
文件名只取最后一段（不许带路径），子目录不许往上爬；写进写痕，留得下痕迹。

### 删掉一个角色

左边树里每个角色**悬停时**会出现一个 **🗑**（详情页右上角也有「删除场景」）。点它会先弹确认框，写清楚要删什么：

- **会删**：场景配置（`backend/scenarios/<id>.json`）、它的全部记忆（`backend/memory/<id>/`）、地盘表里它的登记、
  待办板上**归它自己的那些行**（`@归属` 是它）
- **不删**：台账、写痕、回执 —— 那是历史，不是它的私产
- **常驻会话**：引擎没有删除接口 ⇒ 只能**归档**（从侧栏收起来，数据还在，随时能恢复）
- **记忆不是真删**：会**移到回收站** `backend/data/trash/<角色>-<时间戳>/` ⇒ 删错了能找回来：
  ```bash
  node backend/dev/还原场景.mjs                 # 列出回收站
  node backend/dev/还原场景.mjs <目录名>        # 放回去（配置 + 记忆 + 地盘登记都还原）
  ```

> ⛔ **规则负责人（命令）删不掉** —— 删了它，A/C 档（规矩与工具）就没人能改了。
> 要换人，先把 `territory.json` 里的 `ruleOwner` 改成别人。

### 批量搭一批角色

搭角色/登记地盘的脚本里写死了机主自己的角色名单与地盘，属于**本地资料，不入库**
（本地保留，需要时直接跑）。仓库里提供的路子只有两条：注册页界面，或手写 `backend/scenarios/<id>.json`。

## 会话绑定是怎么工作的（★ 核心）

引擎只用一个 localStorage 键记住「上次会话」：

```
dsh.sessions.current  →  { sessionId: "…" }
```

它**不区分标签、不区分面板** ⇒ 两个面板共用一个 origin 就会互抢
（实感：左右两个窗口都变成同一条会话、每隔几秒跳一下）。

工作台做了三件事：

1. **一板一端口** —— 每个 AI 面板分配一个独立代理端口（3082、3083…），
   端口不同 = origin 不同 = localStorage 天然隔离。**从根上避免鬼绑定。**
2. **写键直达** —— `frontend/web/pin.js` 是阻塞式 `<script>`，在引擎应用启动**之前**执行，
   直接把目标 `sessionId` 写进键里 ⇒ 打开面板即命中那条会话，不会先闪一下别的会话。
3. **点行兜底** —— 写键没生效（会话被改名/归档/换过）时，按标题在会话列表里找到那一行并点它。
   - 会话行 = `div[role="treeitem"][aria-selected]`，**行里没有会话 id**
   - 标题在 `<span class*="title">`，行文本还带相对时间 ⇒ 不能拿整行文本做完全相等判断
   - 分组头 = `div[role="treeitem"][aria-expanded]`，点了只展开分组，**绝不能点**

**判据只能是画面**：面板标题栏那行小字就是证据 ——
`✓ 已钉` / `✓ 已钉（点行）` / `✗ 找不到会话行` / `⚠ 需刷新一次`。
鼠标悬停能看到完整诊断（目标 id、存储里的当前会话、画面上的会话、会话行数）。
**点那行小字 = 忘掉记住的标题，重新按会话名匹配。**

> 判「画面上是哪条会话」要看**两个来源**（`frontend/web/pin.js`）：
> ① 侧栏里选中的**会话行**（`div[role="treeitem"][aria-selected]`）
> ② **document.title**（引擎把会话名放在「<会话名> — DeepSeek Harness」里）
>
> ⚠ 只看①会误判：引擎的「对话」页签**也有** `aria-selected="true"`，
> 会被当成会话标题；而且面板 iframe 窄的时候侧栏压根不渲染（树里 0 条会话行）。
> 所以两个都收下，谁匹配上算谁 —— 面板窄的时候靠 document.title 判。

## 派单机制（跨角色派活 + 回执闭环）

> 机制原文在 `backend/memory/_共享记忆/派单机制.md`，AI 也读它。

### 派单 ≠ 公告

| | 派单 | 公告 / 知悉 |
|---|---|---|
| 对方要做什么 | **动手** | 只是知道 |
| 要不要唤醒 | ✅ **真唤醒**（发进对方会话） | ❌ 只落盘 |
| 判据 | 「请你改 / 派单 / 做完回一句 / 复验」 | 「以后就是这么办了」 |

工作台会**自己判**：正文里没有动作动词 ⇒ 按公告处理，只落盘不唤醒（唤醒要花对方一轮）。

### 派单正文：四件套（缺一件发不出去）

```
① 现象    现在是什么样子（可观察的，不要形容词）
② 照哪做  哪份文档的哪一节 / 哪个工具（唯一出处）
③ 怎么验  做完跑哪个检查、看到什么算通过
④ 回一句  明确要回执，并写「我在等你的回执」
```

少任何一件，工作台**直接拒绝发** —— 因为缺一件对方就得追问。

### 回执闭环怎么闭合的

1. 派单 ⇒ 引擎 RPC `session/prompt` **真唤醒**对方的会话（不是「我写进文件了」）
2. 派单正文里给出**回执要写到哪个文件**：`backend/memory/_共享记忆/_回执/<编号>.md`
3. 对方干完 → 写回执（结论 + 证据 + 落盘路径）→ 工作台扫到文件 ⇒ **台账自动填 ack（销账）**
4. 发起方可发**收尾知悉**（最多 1 条）⇒ 这条线结束

> 判据：**「活干完了但对方还不知道」= 没干完。**

### 三条硬上限（防 AI 互相客套烧钱）

| 上限 | 值 | 工作台怎么做 |
|---|---|---|
| 同一件事的消息数 | **≤ 3 条** | 第 4 条直接拒 |
| 单条长度 | ≤ 200 字 / ≤ 10 行 | 超了直接拒 |
| 末行 | `【结束】` | 自动补 |
| 纯确认语 | ⛔ 不许发 | 「收到/好的/谢谢」直接拒 |

### 台账与两个查询

台账在 `backend/data/dispatch-ledger.jsonl`（一行一条）。面板上永远能看到这两个查询：

| 查询 | 回答 |
|---|---|
| **我发出还没人回的** | 我欠不欠催？ |
| **别人在等我回的** | 我是不是让别人空等？ |

超时没回 ⇒ 状态变成 **未回执**（进「我发出没回」清单）。

## 分诊出口（唯一对口可执行）

> 原文的抓手：「一个『分诊』工具扫一遍（台账未办结 / 看板 / 体检 ⛔ / 定位卡未办结）⇒ 出『有主 / 无主』两张单。」

分诊面板扫四个来源，出两张单：

| 来源 | 扫什么 |
|---|---|
| **台账未办结** | 派了单还没回执的（超时的单独标 ⏰） |
| **通知看板** | 还没销账的通知行 |
| **体检 ⛔** | AI 面板没绑会话 / 绑的会话在引擎里没了 |
| **定位卡未办结** | 定位卡里还留着 `TODO` |

### 无主的活 ⇒ 自动给出建议归属

「唯一对口」表在 `territory.json` 的 `soleResponsibility` 里，带关键词。分诊按关键词判：

```
• [待办（无归属）] 清理 data/ 目录里跑完的旧日志
    ⇒ 建议 运维（清理｜命中：清理）
      判据：所有清理类活 → 运维；别的角色不许自己删东西，只能发「清理请求」
    [派给 运维] [我自己做] [问机主]

• [待办（无归属）] 查一下 DSH 最新的插件清单，整理成笔记
    ⇒ 建议 调研（查资料/做笔记｜命中：笔记）

• [待办（无归属）] 随便看看
    ⇒ 没有对口角色 ⇒ 问机主一句（拿不准就别猜着办）
```

> **「没有对口角色」是正常答案，不是失败。** 原文就是这句：「拿不准 ⇒ **问机主一句**（别猜着办）」。

点「派给 运维」会**直接预填派单台**的发给谁和主题 —— 你只管补齐四件套再发。
点「我自己做」⇒ 台账落一行（原文要求）。

## 修改权分档（谁能改什么）

> 机制原文在 `backend/memory/_共享记忆/修改权分档.md`，地盘表在 `territory.json`。

这张表不是给人看的约定，是**机械闸**。

### 五档

| 档 | 范围 | 谁能改 | 越界的后果 |
|---|---|---|---|
| **A** 共享·宪法 | 全局铁律 / 规范 / 协作规则（`AGENTS.md`、`territory.json`…） | 只有**规则负责人** | 规矩互相打架，每个角色记的都不一样 |
| **C** 共享·工具与运行时 | 工具目录 / 插件 / MCP / 技能目录 / 索引（机器自动生成） | 同上；别人**只能提请求** | 一个人改了工具，其他人全部静默失效 |
| **B** 共享·板与台账 | 待办板 / 通知看板 / 回执目录 / 台账 | 各角色**写自己那些行** | 删了别人的行 = 别人的活凭空消失 |
| **D** 自己的专属 | 自己的角色配置 / 身份卡 / 记忆 | 自己改 | 改「自己的规矩」没告知负责人 ⇒ 规矩悄悄分叉 |
| **E** 别人的专属 | 别人的场景、别人的记忆 | ⛔ **一个字都不许写** | 直接污染对方的判断 |

### 三道机械抓手

| 抓手 | 干什么 | 接口 |
|---|---|---|
| **受闸写接口** | 改任何东西之前先判，判不过就**拒写** | `POST /api/write` |
| **越界审计** | 扫每个角色会话的日志（write/edit/bash），看谁动了谁的地盘 | `GET /api/authority/audit` |
| **派单带边界** | 把「你只能写哪三处」写进对方收到的单子里 | 派单正文自动追加 |

判不过时会**直接告诉你该走哪条路**：

```
✗ 拒绝  E 别人的专属  归属 command
这是「command」的地盘 ⇒ ⛔ 一个字都不许写。只能提请求。

要改 ⇒ 只能提请求（一次派单）：
  发给：command
  ① 现象：…  ② 照哪做：…  ③ 怎么验：…  ④ 回一句：…
```

### 实测：闸门真的拦得住

派单让「调研」往 `backend/memory/command/` 写一行（那是命令的地盘），调研场景的 AI：

1. 认出这是 E 档 ⇒ **没写**
2. 改用受闸接口验闸 ⇒ **HTTP 403**（判不过就拒，文件一个字节没落）
3. 跑 `ls` 确认文件不存在、`stat` 确认命令目录 mtime 没变
4. **做了正对照**：同一个接口写 B 档看板 ⇒ HTTP 200（闸不是一律拦截，是按档放行）
5. 写回执说明结论

审计器随后扫出：**0 次越界**。

> 审计器分读写很准：`tail -1 backend/memory/other/x.md` 是**读**，`node -e fs.appendFileSync(...)` 才是**写**。
> 不分的话满屏假警报，机制当场就废了。这条踩了四轮才做对：

> | 假警报来源 | 修法 |
> |---|---|
> | `readFileSync` 被当成写 | 写 API 用**白名单**，不能用「凡是 `*Sync` 都算」 |
> | `grep -rn "unlinkSync" backend/lib/` 里的字样 | 写 API 必须是「**被调用**」（后面跟左括号），不是被提到 |
> | `grep "rm(" backend/lib/ backend/server.mjs` 里的 `rm(` | 引号里的内容**先遮罩**再扫 shell 语法 |
> | `=>` 箭头函数 | 重定向的正则排除 `=`/`-`/`>` 前面的 |

体检里的负例自测把正例和负例放一起跑：**该拦的全拦住，该放行的一条不误报**。

## 写痕与撞车（同一文件两个写入者）

> 原仓库事故复盘的最后一条未解失效模式：
> 「两个会话改同一个文件，改动神秘消失」——
> 根因：没有「同一文件两个写入者」约束；
> 修法：**写盘前重读**、**写完自证别人的改动还在**；**同路径的活只留一个写入者**。

### 三道机械约束

| 约束 | 做什么 | 触发时 |
|---|---|---|
| **写盘前重读** | 写的人报一个 `baseSha`（他读的是哪一版），对不上就拒写 | HTTP 409「你读的那一版已经过时了」 |
| **写入权** | 同一路径同时只留一个写入者（租约 30 分钟，持有者才能释放） | HTTP 409「这个文件现在归「X」写」 |
| **写完自证** | 写完检查**别人**写的行还在不在；盖掉了就**回滚拒写** | HTTP 409「这一版会把 N 行别人写的改动盖掉 ⇒ 已拒写」 |

### 撞车检测

写痕来自两个数据源：**会话日志**（AI 自己用 `write`/`edit` 写的）+ `backend/data/writes.jsonl`（受闸写接口写的）。
因为 `write` 工具带完整内容、`edit` 带 old→new（能重放），**每个文件在每个时刻的内容都能重建** ⇒

```
后一次写的内容里，如果前一个角色写的行不见了 ⇒ 抓到了「改动神秘消失」
```

分两级报：

| 级别 | 含义 |
|---|---|
| ⚠ 同路径两个写入者 | 两个角色都动过这个文件（**没丢行** —— 正常的共享板追加） |
| ⛔ 改动神秘消失 | 后一次写把前一个角色的行盖掉了（**真出事**） |

### 实测：机制自己抓到了我的 bug

我派两个角色各往共享待办板追加一行。调研场景**没能写成**，回执里把根因查到了：

> 「写入权被 `ops` 持有（14:47:40 拿的，30 分钟有效）⇒ 我一行都没写。
> 根因：写痕负例自测 —— **写入权是在自证之前抢的，回滚不会还回**；
> `finally` 又用裸写还原待办板、也没 releaseClaim ⇒ **每跑一次自测，就给「运维」留一条 30 分钟的待办板租约**。」

它还明确拒绝了两条捷径：「不用裸文件工具改待办板（那会绕过租约与自证）」
和「不冒充 ops 去 release（释放权只在持有者手上，冒充=越权）」。

⇒ 我修了两个地方：**拒写时交还租约**、**自测结束释放租约**。修完重派，调研 25 秒就把那行写进去了，
两个角色的行都在，谁也没被盖掉。

> 这就是「同一个文件两个写入者」这条机制真正的价值：
> 它不只防 AI 之间互相覆盖，也防**机制自己**把路堵上。

## 操作留痕（这个场景里发生过的一切）

> 「我在「阅读」里到底干了什么？」——以前没人能回答：
> 人在界面上的动作没留痕（点开哪本书、更新到第几页，一关页面就没了），
> AI 的动作只散在会话日志里，跟人的动作对不上时间线。
>
> 现在两边汇成**一条时间线**：**谁**（人/AI/系统）· **做了什么** · **动了哪一样东西** · 结果如何。

### 记在哪

| 内容 | 位置 |
|---|---|
| 台账（运行期数据，不进版本库） | `backend/data/acts/<场景id>.jsonl` —— 一行一条，只追加 |
| 导出的 Markdown（人看的那份） | `backend/memory/<场景id>/操作留痕.md`（面板上点「导出 Markdown」） |

### 时间怎么算（⚠ 存 UTC、显示本地）

| | |
|---|---|
| **存** | 台账里写 **ISO UTC**（`2026-11-17T09:09:07.930Z`）+ `at`（epoch ms）⇒ 排序、跨时区都不会错 |
| **显示** | 一律转成**本地时间**再给人看（`backend/lib/actlog.mjs` 的 `localTime/localDay/localStamp`；前端 `wbLocalTime/wbLocalDay`） |
| **今天 N 条** | 按**本地日期**算（不是 UTC 日期 ⇒ 夜里 0 点前后的记录不会被算到第二天） |

> ⚠ 踩过的坑：以前显示时直接切 ISO 字符串 `ts.slice(11,19)` ⇒ 显示的是 **UTC**，
> 本地 CST+8 就整整差 8 小时（「每个场景的留痕时间都是错的」）；
> 夜里 0 点前的记录连**日期头**都会落到前一天。
> 判据只此一处：**凡是给人看的时间，一律走本地时间函数**。

### 三条来源

| 来源 | 谁记的 | 例子 |
|---|---|---|
| **界面操作** | 前端埋点（`wbAct()`） | 选中场景 · 进入场景 · 打开书 · 打开条目 · 打开会话 |
| **服务端改动** | 后端**就地**留痕（不靠前端自觉） | 更新阅读进度 · 加一本书 · 上传文件 · 写记忆 · 写便签 · 绑定项目目录 |
| **会话里的动作** | 从会话日志读（只读） | AI 的工具调用（bash/read/edit/write…）+ **人自己在场景里说的话** |

> 第三条是关键：常驻会话里发生的事只存在于会话日志 ⇒ 不读它，「所有操作」就少了最要紧的一半。

### 显示层：折掉噪声（**台账照旧全记**）

实测一个场景的台账 157 条里，136 条（87%）是「选中场景 / 进入场景」这种纯点击；
再加上会话里 AI 的每次 bash/read ⇒ 界面上 250+ 行，真事淹没在噪声里。

| 留痕 | 界面怎么显示 |
|---|---|
| 导航动作（选中场景 / 进入场景） | 一天合成一行：`16:09:00 人 进出场景 ×10　选中场景 5 · 进入场景 5` |
| AI 的工具调用 | 按工具名合成一行：`00:00:06→16:36:06 AI edit ×37`，**点开看明细** |
| 有结果的动作（打开书 / 写记忆 / 更新阅读进度 / 写身份卡…） | 一条一行，不折 |

- 面板顶部会写清楚：**「原始 253 条 → 折成 36 行」**（别让人以为记录丢了）
- ⚠ 折叠**只动显示**：`backend/data/acts/*.jsonl` 一条没少，导出的 Markdown 也仍是全量（按本地时间 + 日期头）

### 在哪看

- **场景页右栏**：一张「操作留痕」卡（最近 8 条）⇒ 点「打开场景看留痕」直接跳到详情页的「留痕」页签。
- **场景详情页 · 项目信息面板**：多一个 **「留痕」页签** —— 完整时间线，可按 人/AI 筛，可导出 Markdown；
  停留在这个页签时它会自己刷新（切走就停）。
- **接口**：`GET /api/actlog?scene=reading&ai=1`。

### 判据只此一处

`backend/lib/actlog.mjs`：`append()` 是唯一写入口（只 append 一行 jsonl，不碰任何业务文件），
`read()` 是唯一读入口，导出的 Markdown 也从同一份数据生成。

> ⚠ 留痕失败**不许**拖垮正事 ⇒ 写台账出错只吞掉，界面照常用。

## GPU 优先 + 负载闸

> 机制原文在 `backend/memory/_共享记忆/GPU优先.md`。

### GPU 的唯一判据

**「这个活的数据是不是要在这台机器上算？」** 不是 ⇒ 别动 GPU 的心思。

| ✅ 能上 GPU | ⛔ 用不上（真相） |
|---|---|
| OCR（文字识别）· 视频编码 · 三维渲染 | 大模型推理 = 调远端 API，本地 GPU 完全不参与 |

判据**只写在一处**：`backend/lib/gpu.mjs` 的 `shouldUseGpu()`，接口 `POST /api/gpu/verdict`。
拿不到判据 ⇒ **照 CPU 跑并记 why**（降级不是失败）。

### 退 CPU 是另一套参数

| 约束 | 值 |
|---|---|
| 进程数 | 单进程 |
| 线程数 | `OMP_NUM_THREADS=2` / `MKL_NUM_THREADS=2` |
| 优先级 | `BelowNormal` |

### 验收三条（「能跑通」不算证据）

```
① providers 列表里出现 CUDA（不是 CPUExecutionProvider 兜底）
② 有量化指标（秒/页 · fps · 采样速度）
③ 显存占用有数字
```

「三类活分流」面板会把三条逐条列出来，缺一不算数。

### 负载闸：派活前先看机器

| 负载 | 允许做什么 |
|---|---|
| 任一资源 **≥90%** | ⛔ 不派单、不唤醒别的会话 |
| 任一资源 **≥95%** | ⛔ 连体检/构建/全盘扫描都别跑 |

判据在 `backend/lib/loadgate.mjs`，**只此一处定义**，调用方只认 `canDispatch`。
**派单接口会先过这道闸** —— 机器接不了活的时候叫醒别的会话，只会让大家一起变慢。

> ⚠ **macOS 的内存口径必须单独修**：Node 的 `os.freemem()` 在 macOS 上只算 free pages，
> 把 inactive/purgeable 全漏掉 ⇒ 一台 16 GB 的机器明明还有 5 GB 可用，它报「用了 99.9%」，
> 负载闸会永远喊停。这里改用 `vm_stat` 的 free+inactive+purgeable+speculative。
> （Windows 版原样搬过来最容易踩的坑。）

## 体检（24 项）

界面：场景页的「体检」面板 / 工作台仪表盘的「自检」按钮。接口：`GET /api/doctor`。

覆盖：引擎连通 · 负载闸口径 · 派单台账一致性 · 回执目录 · 写入权租约 ·
写痕与撞车 · 地盘表完整性 · 角色 json 合法性 · **记忆结构** · **§〇 红线（≤4KB）** ·
**宪法在位** · **索引在位** · 自测负例（该拦的拦住、该放行的放行）。

> 体检里跑的自测是**进程内**的（`backend/lib/selftest.mjs`），不联网、不起子进程 ——
> 早期版本让子进程回调同一个服务，父子互等直接死锁。

> ⚠ `GET /api/doctor` 的 `ok` 的意思是「**所有项都绿**」——
> 只要有一项红它就是 `false`，但 `report.rows` 里 24 项**照样全在**。
> 体检面板按「报告在不在」判断（早先按 `ok` 判断 ⇒ 有红项就只显示一句「体检跑不了」，把报告全吞了）——
> 要看体检的人，恰恰要看到**是哪一项坏了**。

## 出事查哪层（按症状）

| 症状 | 先查 | 多半是 |
|---|---|---|
| 侧栏没有「工作台」按钮 | 插件管理器里「工作台」是不是开着 | 插件被停用了；或浏览器没刷新（客户端模块要刷新页面才加载） |
| 工作台区域一片空白 | `GET /workbench/api/state` | 插件没起来；或工作台目录找不到了（配 `root`） |
| 点了「工作台」但没反应 | 浏览器控制台 | 客户端模块没加载 ⇒ 刷新页面 |
| AI 面板一片黑 / 显示 401 | 右上角「引擎」贴 token | 浏览器没有引擎 cookie（独立模式才需要） |
| AI 面板一片乱码 | `backend/dev/check-embed.mjs` | 代理把压缩过的正文当明文插脚本了（已修：转发前去掉 accept-encoding） |
| AI 面板空白 + 控制台报 "did not preload" | `backend/dev/check-embed.mjs` | 代理重写了引擎的 `??@包名` 路径（已修：只做字符串手术，不用 URL 重新序列化） |
| AI 面板里的请求报 403 | `backend/dev/check-embed.mjs` | Origin 与改写后的 Host 对不上（已修：一起改） |
| 右上角「引擎未连」 | `GET /api/engine/status` | 引擎没起，或 cookie 没连上 |
| 面板显示「未知面板类型」 | `frontend/web/panels.js` | `type` 没注册（**不报错、不崩**） |
| 卡片目录里少了某个角色 | `backend/scenarios/` | 文件名 ≠ `id`，或 json 解析失败 |
| 切角色还是上条会话 | 面板小字 + 会话管理面板 | 绑定三字段没写全，或会话被归档了 |
| 左右两个面板变成同一条会话 | — | 面板端口分配重复了（正常不会发生） |
| 改了 json 没变化 | 切走再切回 | 面板是**重建**的，不是热更新的 |
| 改了 `backend/lib/*.mjs` 没生效 / 报 `does not provide an export named ...` | 重启 `dsh web` | 插件热重载只给 `backend/server.mjs` 加时间戳破缓存，`backend/lib/` 下的模块走 Node 的模块缓存 —— 改它们**必须重启进程** |
| `§〇 当前交接` 超 4KB | 体检面板 | 红线了，该拆分 |
| 派单发出没回执 | 派单台 + 目标会话 inbox | 对方会话没跑起来 / 回执没写到指定文件 |
| 派单发不出去，报「缺某一件」 | 表单 | 四件套缺一件 —— 这是故意的，不是 bug |
| 派单发不出去，报「投递失败」 | 目标角色 json | 那个角色还没绑会话（`sessionId` 是空的） |
| 派单被拒，报「机器接不了活」 | `GET /api/loadgate` | CPU/内存 ≥90% —— 等机器缓过来 |
| 对方一直不回执 | 目标会话 inbox | 接收方的回合在等审批（写回执要提权） |
| 面板报「⛔ 这是别人的地盘」 | `GET /api/authority/check` | 正常 —— 这是闸在拦。要改就发派单 |
| 审计报一堆假越界 | `GET /api/authority/audit` | 审计分读写分岔了：读命令被当成写命令 |
| 分诊建议的归属不对 | `territory.json` 的 `keywords` | 没覆盖这个说法 |
| 写文件被拒 409「现在归 X 写」 | `GET /api/writes` | 租约还没到期（30 分钟）或持有者没释放 |
| 写文件被拒 409「会把别人写的盖掉」 | `GET /api/writes` | 你这版把别人的行弄没了 ⇒ 重读后把那些行带上 |

## 与原仓库的差别（为什么这么改）

| | 原仓库 | 这里 |
|---|---|---|
| 外壳 | Electron（4895 行主进程，172 个 IPC） | **DSH 插件**（住在引擎进程里，跨平台，零依赖） |
| 引擎内嵌 | Electron `<webview>` + `persist:` 分区 | `<iframe>` + **一板一端口**（同源隔离效果相同） |
| 钉会话 | `executeJavaScript` 注入一大段脚本 | 代理在 HTML 里注入 `pin.js`（逻辑同源，更短） |
| 记忆结构 | 四个文件（定位卡/场景画像/场景私有记忆/§〇） | **合并为一个 `项目信息.md`** + 身份卡（视频那一版） |
| 首页 | 场景标签栏 | **卡片目录**（视频那一版） |
| 操作方式 | 命令行脚本为主 | **纯界面**（命令行已移除） |
| 路径 | Windows 反斜杠字面量 + 盘符 | 全部 `path.join` + 环境变量兜底 |
| 启动 | 双击 `.vbs` | `dsh web`（工作台跟着引擎一起起） |

原仓库里那些**硬编码路径、双 `.dsh`、端口写死 3080/3083 不一致**的坑，这里都没有继承。
